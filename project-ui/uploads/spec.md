## 1. ภาพรวมระบบ

### 1.1 วัตถุประสงค์
พัฒนาระบบบริหารจัดการการเรียนรู้ (Learning Management System) ที่ใช้ได้ **2 รูปแบบในระบบเดียว**
1. **ภายในสถาบัน:** นักศึกษาและบุคลากรเรียนรายวิชาที่แต่ละคณะ/หน่วยงานเปิดสอน
2. **คอร์สสาธารณะ:** เปิดคอร์สให้บุคคลภายนอกสมัครเรียน โดยเฟสแรกยังเป็นคอร์สฟรี ส่วนการชำระเงินจะทำในเฟส 2

### 1.2 ขอบเขต (Scope)
| อยู่ในขอบเขตเฟส 1 | ไม่อยู่ในขอบเขตเฟส 1 |
|---|---|
| จัดการผู้ใช้ 4 role, คณะ/หน่วยงาน | ระบบชำระเงิน/คูปอง (เฟส 2 แต่ schema เผื่อไว้แล้ว) |
| สร้างคอร์ส บทเรียน (วิดีโอ, PDF, Rich text, Live) | DRM วิดีโอ (Widevine/FairPlay) |
| Quiz/Exam, Assignment, Gradebook, Certificate | Mobile native app (ใช้ responsive web แทน) |
| ประกาศ, แจ้งเตือน (In-app/Email/LINE), Q&A, รีวิว | หลายภาษา (เฟส 1 มีเฉพาะภาษาไทย) |
| ป้องกันการ capture หน้าจอแบบหลายชั้น + watermark | SCORM/xAPI, เชื่อมระบบทะเบียน (พิจารณาเฟสถัดไป) |
| รายงาน/Dashboard, Audit log | |

### 1.3 Tech Stack (กำหนดโดยเจ้าของระบบ)
| ส่วน | เทคโนโลยี |
|---|---|
| Framework | **Next.js 16 (App Router)** + **TypeScript** |
| ORM / Database | **Prisma** + **PostgreSQL** |
| Styling / UI | **Tailwind CSS v4** + **shadcn/ui** |
| Package manager | **pnpm** |
| Authentication | Better Auth (Google OAuth + Email/Password) |

| Hosting | ยังไม่กำหนด ออกแบบให้ย้ายผู้ให้บริการได้ (ดู system-design §10) |

## 2. ผู้ใช้งานและบทบาท (Actors & Roles)

| Role | รหัส | คำอธิบาย |
|---|---|---|
| ผู้ดูแลระบบสูงสุด | `SUPER_ADMIN` | ตั้งค่าระบบ, จัดการผู้ใช้/คณะ/หมวดหมู่ทั้งหมด, ดู audit log และรายงานรวม |
| ผู้ดูแลคณะ/หน่วยงาน | `DEPT_ADMIN` | จัดการผู้ใช้และคอร์สในคณะของตน, อนุมัติเผยแพร่คอร์ส, ลงทะเบียนผู้เรียนแบบกลุ่ม, ดูรายงานของคณะ |
| ผู้สอน | `INSTRUCTOR` | สร้าง/แก้ไขคอร์สของตน, สร้างบทเรียน แบบทดสอบ และงาน, ตรวจงาน, ให้คะแนน, ตอบ Q&A, ประกาศ |
| ผู้เรียน | `STUDENT` | ค้นหาคอร์ส, ลงทะเบียน, เรียน, ทำแบบทดสอบ, ส่งงาน, ดูคะแนน, รับใบประกาศ, รีวิว |
| ผู้เยี่ยมชม | (ไม่ login) | ดู catalog, หน้ารายละเอียดคอร์ส, บทเรียนที่เปิดให้ดูตัวอย่าง (preview) และตรวจสอบใบประกาศ |

**กติกาการกำหนด role:** ผู้สมัครใหม่ทุกคนได้ role `STUDENT` เป็นค่าเริ่มต้น การเปลี่ยน role ทำได้เฉพาะ `SUPER_ADMIN` ส่วน `DEPT_ADMIN` ทำได้ภายในคณะตนเองและเปลี่ยนได้สูงสุดแค่ `INSTRUCTOR`

## 3. Functional Requirements (FR) และ Feature Checklist

### 3.0 โครงสร้าง Checklist มาตรฐาน (ใช้กับทุกโมดูล)
แต่ละโมดูลต้องผ่าน **Definition of Done (DoD)** 7 ข้อนี้ก่อนจะถือว่าเสร็จ:

```
- [ ] DB    : Prisma model + migration + index + seed data
- [ ] Server: queries.ts (อ่าน) / actions.ts (เขียน) + ตรวจสิทธิ์ใน Data Access Layer
- [ ] Schema: Zod schema ใช้ร่วม client/server + ข้อความ error ภาษาไทย
- [ ] UI    : หน้าจอ responsive (375px / 768px / 1280px) + loading/empty/error state
- [ ] A11y  : keyboard navigation, label, contrast ตาม WCAG AA
- [ ] Test  : unit (Vitest) สำหรับ logic + e2e (Playwright) สำหรับ flow หลัก
- [ ] Audit : บันทึก AuditLog สำหรับการกระทำสำคัญ + อัปเดตเอกสาร
```

รหัสสถานะ: `[ ]` ยังไม่เริ่ม · `[~]` กำลังทำ · `[x]` เสร็จ · Priority: **P0** = ต้องมีใน MVP, **P1** = เฟส 1, **P2** = เฟสถัดไป

## 4. Non-Functional Requirements (NFR)

| ID | หมวด | Requirement |
|---|---|---|
| NFR-01 | Responsive | ออกแบบ mobile-first, breakpoint 375 / 768 / 1024 / 1280px, ไม่มี horizontal scroll, touch target ≥ 44px |
| NFR-02 | Performance | LCP < 2.5s บน 4G, หน้าแรกส่ง JS < 200KB (gzip), ทุก list แบ่งหน้า, มี DB index ครบ |
| NFR-03 | Security | OWASP Top 10, CSRF (Server Actions + SameSite cookie), rate limit, hash รหัสผ่าน (scrypt ผ่าน Better Auth), ตรวจชนิดและขนาดไฟล์ฝั่ง server, sanitize HTML, security headers (CSP, HSTS) |
| NFR-04 | Authorization | Deny by default และตรวจสิทธิ์ใน Data Access Layer ทุกครั้ง (ไม่พึ่ง proxy อย่างเดียว) |
| NFR-05 | Privacy | ปฏิบัติตาม PDPA: consent, export/ลบข้อมูล, เก็บ log ไม่เกิน 1 ปี |
| NFR-06 | Availability | เป้าหมาย uptime 99.5%, backup DB ทุกวัน เก็บย้อนหลัง 14 วัน |
| NFR-07 | Scalability | รองรับผู้ใช้พร้อมกัน ≥ 1,000 คนในเฟสแรก, แอปเป็น stateless เพื่อ scale แนวนอนได้ |
| NFR-08 | Accessibility | WCAG 2.1 AA |
| NFR-09 | Localization | UI ภาษาไทย, ฟอนต์ IBM Plex Sans Thai, วันที่แสดงแบบ พ.ศ. (เก็บเป็น UTC แสดงผลเป็น Asia/Bangkok) |
| NFR-10 | Portability | ไม่ผูกกับ vendor: S3 API, PostgreSQL มาตรฐาน, มี Docker Compose, ใช้ env vars |
| NFR-11 | Maintainability | TypeScript strict, ESLint + Prettier, โครงสร้างแยกตาม feature, CI รัน lint/typecheck/test |
| NFR-12 | Observability | Structured log, error tracking (เช่น Sentry), health check endpoint |

## 5. User Stories หลัก (ตัวอย่าง)
- **Student:** ในฐานะผู้เรียน ฉันต้องการ login ด้วย Google แล้วกด "เรียนต่อ" เพื่อกลับไปดูวิดีโอจากจุดเดิมบนมือถือได้ทันที
- **Student:** ในฐานะผู้เรียน ฉันต้องการได้รับแจ้งเตือนทาง LINE ก่อนกำหนดส่งงาน 24 ชั่วโมง
- **Instructor:** ในฐานะผู้สอน ฉันต้องการสร้างแบบทดสอบที่สุ่ม 20 ข้อจากคลัง 100 ข้อพร้อมจับเวลา เพื่อลดการลอกกัน
- **Instructor:** ในฐานะผู้สอน ฉันต้องการเห็นงานที่รอตรวจทั้งหมดในหน้าเดียวและให้คะแนนพร้อม feedback
- **Dept Admin:** ในฐานะผู้ดูแลคณะ ฉันต้องการนำเข้านักศึกษา 200 คนจาก CSV และลงทะเบียนเข้ารายวิชาในครั้งเดียว
- **Super Admin:** ในฐานะผู้ดูแลระบบ ฉันต้องการดูรายงานผู้ใช้ที่พยายาม capture หน้าจอ เพื่อตรวจสอบการละเมิด
- **Guest:** ในฐานะนายจ้าง ฉันต้องการสแกน QR บนใบประกาศเพื่อตรวจว่าเป็นของจริง
