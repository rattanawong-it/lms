## 2. ลำดับงาน (6 ขั้น)

เรียงตามการพึ่งพา: คะแนนต้องมีก่อนสมุดคะแนน และสมุดคะแนนต้องมีก่อนเงื่อนไขจบที่อิงคะแนน
แต่ละขั้น **จบแล้วเห็นผลได้จริงบนหน้าจอ** และจบด้วย lint + typecheck + test + commit · หยุดให้ตรวจที่จุด ✋

### ขั้น 0 — Spike: PDF ภาษาไทย (ครึ่งวัน ก่อนเริ่มขั้น 1) — ✅ เสร็จ 2026-09-23
ทดลองเรนเดอร์ใบประกาศ 1 หน้าด้วยฟอนต์ Anuphan ให้**สระบน/ล่างและวรรณยุกต์วางถูกตำแหน่ง** (เช่น "ผู้ที่ผ่านการอบรม", "นางสาวกิ่งแก้ว")
เพราะ system-design §5.6 กำหนด `@react-pdf/renderer` แต่ไลบรารีกลุ่มนี้มีประวัติวางวรรณยุกต์ไทยซ้อนผิดที่
ผลของ spike ใช้ตัดสินข้อ Q7 (§6) ก่อนเริ่มขั้น 6 — ถ้าทำตอนท้ายเฟสแล้วไม่ผ่าน จะทำให้ทั้งเฟสค้าง
**ไม่ commit โค้ด spike** · บันทึกผลเป็นภาพตัวอย่างใน PR/ข้อความรายงาน

**ผล spike (2026-09-23) — ✅ ผ่าน มีเงื่อนไข 1 ข้อ** · ทดสอบ `@react-pdf/renderer` 4.9.0 + `qrcode` 1.5.4 กับ Anuphan และ Sarabun ได้ผลเหมือนกัน
- วรรณยุกต์และสระบน/ล่างซ้อนถูกตำแหน่ง (ผู้ ปู่ ที่ นี้ ปั้น ญี่ปุ่น ศักดิ์สิทธิ์ ปั๊ม) · ฎ ฐ ญ หางไม่ชนบรรทัด · QR สแกนได้
- **บั๊ก: ข้อความที่มี `ำ` (U+0E33) ทำให้ตัวอักษรตัวสุดท้ายของข้อความนั้นหายทั้งบนภาพและในชั้นข้อความ**
  เช่น "ปิ่นทองคำ" → "ปิ่นทองคํ", "…เกี๊ยว" → "…เกี๊ย" — fontkit แตก `ำ` เป็นสอง glyph (ํ + า) แต่ layout ตัดตามจำนวนตัวอักษรเดิม
- **แก้ได้ด้วยการแตก `ำ` เป็น `ํา` ก่อนส่งเข้า PDF** — ทดสอบแล้วแสดงครบทุกตัวและหน้าตาเหมือนเดิม
  ข้อแลก: ข้อความที่คัดลอก/ค้นหาจากไฟล์ PDF จะเป็น "ํา" แทน "ำ" (ไม่กระทบหน้า `/verify/[code]` ที่เป็นแหล่งยืนยันจริง)
  → ขั้น 6 ต้องให้**ทุกข้อความ**ที่เข้า PDF ผ่านตัวแปลงจุดเดียว และมี unit test กันคนเผลอส่งข้อความดิบ
- Anuphan ใน Google Fonts เป็น variable font — react-pdf ใช้ได้แค่น้ำหนัก Regular
  ถ้าต้องการหัวข้อตัวหนา ต้องสร้างไฟล์ static (เช่น Bold) จาก variable font ด้วย fonttools ในขั้น 6
- **ข้อสรุป Q7:** ใช้ `@react-pdf/renderer` + `qrcode` ตาม design เดิม

### ขั้น 1 — M07a คลังข้อสอบ
- FR-07.1 คลังข้อสอบรายคอร์ส + tag · ค้นหา/กรองตาม tag และชนิด
- FR-07.2 สร้าง/แก้ข้อสอบ 6 ชนิด — โจทย์เป็น Tiptap (ใส่รูปได้), ตัวเลือก, เฉลย, คำอธิบายเฉลย, คะแนน
  | ชนิด | เก็บเฉลยอย่างไร (ไม่แก้ schema) |
  |---|---|
  | `SINGLE` / `TRUE_FALSE` | `Choice.isCorrect` 1 ตัว |
  | `MULTIPLE` | `Choice.isCorrect` หลายตัว |
  | `MATCHING` | `Choice.text` = ฝั่งซ้าย · `Choice.matchKey` = คำตอบฝั่งขวา |
  | `SHORT_TEXT` | `Choice` ทุกตัวคือคำตอบที่ยอมรับ (เทียบแบบตัดช่องว่าง/ไม่สนตัวพิมพ์) |
  | `ESSAY` | ไม่มีเฉลย — ตรวจมือในขั้น 3 |
- FR-07.7 นำเข้าจาก **CSV และ Excel (.xlsx)** — แสดงตัวอย่างและรายงานแถวที่ผิดก่อนบันทึก (แบบเดียวกับนำเข้าผู้ใช้)
  · ให้ดาวน์โหลดไฟล์แม่แบบทั้งสองรูปแบบ · แปลงทั้งสองรูปแบบเป็นแถวชุดเดียวกันก่อนเข้าตัวตรวจตัวเดียว
- **ลบข้อสอบ = เก็บเข้าคลัง (soft delete)** เพราะ `Answer.question` เป็น `onDelete: Cascade` — ลบจริงแล้วคำตอบของผู้เรียนที่เคยสอบหายตาม (§4 ข้อ S1)
- **Test:** unit ของ schema 6 ชนิด + ตัวอ่าน CSV/XLSX · e2e สร้างข้อสอบครบ 6 ชนิดและนำเข้าทั้ง CSV และ XLSX

### ขั้น 2 — M07b แบบทดสอบ + ทำข้อสอบ
- FR-07.3 ตั้งค่าแบบทดสอบ: จับเวลา, จำนวนครั้ง, สุ่มลำดับข้อ/ตัวเลือก, **สุ่มข้อจากคลังตาม tag และจำนวน**
  (`randomPool`), คะแนนผ่าน, ช่วงเปิด-ปิด · ผูกกับบทเรียนชนิด `QUIZ`
- FR-07.5 ทำข้อสอบที่ `/quiz/[attemptId]` ตาม flow §5.4
  - `startAttempt()` สุ่มแล้ว snapshot ลงใน `questionOrder` — รีเฟรชหน้าไม่ได้ชุดใหม่
  - **เฉลยไม่ออกจาก server เลย** (ไม่อยู่ใน RSC payload) · บันทึกคำตอบทีละข้อทันที (autosave)
  - จับเวลาด้วย `expiresAt` ฝั่ง server · client นับถอยหลังและส่งเองเมื่อหมดเวลา
  - **ไม่ใช้ cron ปิด attempt ที่ค้าง** — ทุกครั้งที่ระบบแตะ attempt ที่เลย `expiresAt` แล้วจะส่งให้เองทันที
    (ผู้เรียนกลับมาเปิด, ผู้สอนเปิดผลสอบ, ตอนคำนวณสมุดคะแนน) ใช้หลักเดียวกับ `expiresAt` ของ Enrollment
  - เนื้อหาข้อสอบอยู่ใน `<ProtectedViewer>` (ลายน้ำ + ห้ามคัดลอก)
- FR-07.4 (ส่วนอัตโนมัติ) ตรวจทุกชนิดยกเว้นอัตนัยตอนส่ง · สูตรเป็น pure function ใน `features/quiz/lib/grading.ts`
- FR-07.6 แสดงเฉลย ทันที / หลังปิดสอบ / ไม่แสดง
- บทเรียน `QUIZ` นับว่า "เรียนจบ" เมื่อ**สอบผ่าน** · ส่ง `quiz` เข้า `meetsCompletionRule()` แล้ว `requireQuizPass` ทำงาน
- **Test:** unit ของ grading ทุกชนิด + การสุ่มจาก pool + เงื่อนไขเวลา · e2e ทำข้อสอบ → ส่ง → เห็นคะแนน,
  หมดเวลาแล้วถูกส่งอัตโนมัติ, ตรวจว่า HTML/RSC ของหน้าข้อสอบไม่มีเฉลยปนมา

### ขั้น 3 — M07c ตรวจอัตนัย + ผลสอบ — ✋ *จุดตรวจที่ 1*
- FR-07.4 (ส่วนตรวจมือ) คิวคำตอบอัตนัยที่รอตรวจ · ให้คะแนน + feedback รายข้อ → attempt เปลี่ยนเป็น `GRADED`
- หน้าผลสอบของผู้สอน: รายชื่อ × ครั้งที่สอบ × คะแนน · เปิดดูคำตอบรายคน
- แจ้งผู้เรียนด้วย `notify(GRADED)` เมื่อตรวจอัตนัยเสร็จ · AuditLog ทุกการให้/แก้คะแนน
- **จุดตรวจ:** M07 ครบทั้งโมดูล — ตรวจประสบการณ์ทำข้อสอบบนมือถือจริงก่อนไปต่อ

### ขั้น 4 — M08 Assignment
- FR-08.1 สร้างงาน: คำสั่ง (Tiptap), กำหนดส่ง, คะแนนเต็ม, นามสกุลไฟล์และขนาดที่อนุญาต, ส่งช้าได้ไหม · ผูกกับบทเรียน `ASSIGNMENT`
- FR-08.2 ผู้เรียนส่งข้อความและ/หรือหลายไฟล์ · ส่งใหม่ได้ก่อนกำหนด (เพิ่ม `attemptNo` ไม่ทับของเดิม)
- FR-08.3 `isLate = submittedAt > dueAt` คำนวณฝั่ง server ตอนส่ง
- FR-08.4 ผู้สอนดูไฟล์ ให้คะแนน เขียน feedback หรือ "ส่งกลับให้แก้" (`RETURNED` = เปิดให้ส่งใหม่แม้เลยกำหนด)
- FR-08.5 คิวงานรอตรวจของผู้สอน · รายการงานใกล้ครบกำหนดของผู้เรียน (แสดงบนหน้าหลัก — การแจ้งเตือนล่วงหน้าอยู่ Phase 3 FR-12.3)
- **เรื่องความปลอดภัยที่ต้องเปิดใหม่:**
  - ผู้เรียนต้องอัปโหลดได้ **เฉพาะในบริบทของงานที่ตนลงทะเบียนอยู่** — presign รับ `assignmentId`
    แล้วตรวจ enrollment + นามสกุล/ขนาดตามงานนั้น (ไม่เปิดให้ STUDENT อัปโหลดทั่วไป)
  - ไฟล์ที่ส่งเสิร์ฟผ่าน route ใหม่ที่ตรวจว่าเป็นเจ้าของงานหรือผู้สอนของคอร์สก่อนออก signed URL
- บทเรียน `ASSIGNMENT` นับว่า "เรียนจบ" เมื่อ**ส่งงานแล้ว** (ไม่ต้องรอตรวจ)
- **Test:** unit ของ late/สิทธิ์ส่งซ้ำ/ตรวจไฟล์ · e2e ส่งงานพร้อมไฟล์ → ผู้สอนตรวจ → ผู้เรียนเห็นคะแนน, ผู้เรียนอีกคนเปิดไฟล์ของคนอื่นไม่ได้

### ขั้น 5 — M09 Gradebook
- FR-09.1 รายการคะแนนจากแบบทดสอบ/งานถูกสร้างอัตโนมัติ + รายการกรอกเอง (`MANUAL`)
- FR-09.2 น้ำหนัก % (รวมต้องเท่ากับ 100 ก่อนจึงคำนวณเกรด) + **เกณฑ์ตัดเกรดต่อคอร์ส** (§4 ข้อ S2)
  · เกณฑ์ตั้งต้นใช้ค่าชั่วคราวตาม Q6 ไปก่อน เก็บเป็นค่าคงที่จุดเดียว แล้วเปลี่ยนเป็นเกณฑ์จริงเมื่อได้รับ
- FR-09.3 ตารางผู้เรียน × รายการ แก้คะแนนในช่องได้ · AuditLog ทุกช่องที่แก้ (ค่าเดิม/ค่าใหม่)
  · คะแนนที่ผู้สอนแก้ทับจะไม่ถูกผลสอบครั้งใหม่ทับกลับ (§4 ข้อ S3)
- FR-09.4 ผู้เรียนเห็นเฉพาะคะแนนของตัวเอง
- FR-09.5 Export เป็น **CSV (UTF-8 มี BOM) และ Excel (.xlsx)**
- เงื่อนไขจบ `minScore` คิดจาก**คะแนนรวมถ่วงน้ำหนักในสมุดคะแนน** (Q4)
- ตารางกว้าง → ใช้ `overflow-x-auto` + คอลัมน์ชื่อตรึงซ้าย · บนจอ 375px แสดงเป็นการ์ดรายคนแทนตาราง
- **Test:** unit ของสูตรถ่วงน้ำหนัก + ตัดเกรด + ปัดเศษ Decimal · e2e แก้คะแนน → audit log มีบันทึก, ผู้เรียนเห็นแค่แถวตัวเอง

### ขั้น 6 — M10 Certificate + ปิดเฟส — ✋ *จุดตรวจที่ 2*
- FR-10.2 แม่แบบต่อคอร์ส (`Course.certificateTemplate`): โลโก้, ลายเซ็น, ข้อความ + ตัวแปร `{ชื่อ} {คอร์ส} {วันที่} {รหัส}`
  พร้อมตัวอย่างก่อนบันทึก
- FR-10.1 ออกอัตโนมัติที่จุด `justCompleted` เดิม ตาม flow §5.6 · สร้าง PDF หลัง commit ด้วย `after()`
  ไม่ให้ผู้เรียนต้องรอเรนเดอร์ตอนกดเรียนจบ
- FR-10.3 รหัสสุ่มไม่ซ้ำรูปแบบ `LMS-2026-XXXXXX` (ตามที่ระบุใน schema) + QR ไป `/verify/[code]` (หน้าสาธารณะ แสดงชื่อ คอร์ส วันที่ สถานะ)
- FR-10.4 `/certificates` ของผู้เรียน + ดาวน์โหลดผ่าน signed URL (ไม่ครอบด้วย ProtectedViewer — เป็นเอกสารของผู้เรียนเอง)
- FR-10.5 เพิกถอนพร้อมเหตุผล · หน้า verify ขึ้น "ถูกเพิกถอน" · AuditLog
- แจ้ง `notify(CERTIFICATE)`
- **e2e ปิดเฟส:** สร้างคอร์สที่มีแบบทดสอบ + งาน → ผู้เรียนทำข้อสอบผ่าน + ส่งงาน → ผู้สอนตรวจ
  → คะแนนเข้าสมุดคะแนน → ครบเงื่อนไข → ได้ใบประกาศ → เปิด `/verify/[code]` แบบไม่ล็อกอินได้

## 7. ความเสี่ยงที่มองเห็นตอนนี้

| ความเสี่ยง | ผลกระทบ | แนวทาง |
|---|---|---|
| เฉลยรั่วไปที่ client | ข้อสอบเสียทั้งชุด | query ของหน้าทำข้อสอบ `select` เฉพาะฟิลด์ที่แสดง (ไม่ดึง `isCorrect`/`matchKey`) + e2e ค้นเฉลยใน HTML/RSC |
| ผู้เรียนแก้เวลาเครื่องหรือเปิดหลายแท็บ | สอบเกินเวลา / ได้ชุดข้อใหม่ | ตัดสินด้วย `expiresAt` ฝั่ง server เท่านั้น · `startAttempt` คืน attempt เดิมที่ยังเปิดอยู่แทนการสร้างใหม่ |
| สองคนส่ง/แก้คะแนนพร้อมกัน | คะแนนในสมุดไม่ตรงกับผลสอบ | sync `Grade` ใน transaction เดียวกับการส่ง/ตรวจ · unique `[gradeItemId, userId]` มีอยู่แล้ว |
| ปัดเศษคะแนน | เกรดคลาดที่ขอบ (79.995 → A หรือ B+) | คำนวณด้วย Decimal ทั้งเส้น ปัดครั้งเดียวที่ 2 ตำแหน่งตอนแสดง · unit test กรณีขอบ |
| วรรณยุกต์ไทยใน PDF | ใบประกาศใช้จริงไม่ได้ | spike ขั้น 0 ก่อนลงมือทั้งเฟส |
| เปิดให้ STUDENT อัปโหลด | ช่องทางใหม่ให้ยัดไฟล์ขยะ/มัลแวร์เข้าระบบ | ผูกกับ `assignmentId` + enrollment, จำกัดนามสกุล/ขนาดตามงาน, magic bytes เดิม, rate limit |
| ตารางสมุดคะแนนบนมือถือ | Chrome ย่อทั้งหน้า (CLAUDE.md §6) | มุมมองการ์ดบนจอเล็กแทนตารางกว้าง |
