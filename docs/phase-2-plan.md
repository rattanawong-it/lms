## 2. ลำดับงาน (6 ขั้น)

เรียงตามการพึ่งพา: คะแนนต้องมีก่อนสมุดคะแนน และสมุดคะแนนต้องมีก่อนเงื่อนไขจบที่อิงคะแนน
แต่ละขั้น **จบแล้วเห็นผลได้จริงบนหน้าจอ** และจบด้วย lint + typecheck + test + commit · หยุดให้ตรวจที่จุด ✋

### ขั้น 0 — Spike: PDF ภาษาไทย (ครึ่งวัน ก่อนเริ่มขั้น 1) — ✅ เสร็จ 2026-09-23
ทดลองเรนเดอร์ใบประกาศ 1 หน้าด้วยฟอนต์ Anuphan ให้**สระบน/ล่างและวรรณยุกต์วางถูกตำแหน่ง** (เช่น "ผู้ที่ผ่านการอบรม", "นางสาวกิ่งแก้ว")
เพราะ system-design §5.6 กำหนด `@react-pdf/renderer` แต่ไลบรารีกลุ่มนี้มีประวัติวางวรรณยุกต์ไทยซ้อนผิดที่
ผลของ spike ใช้ตัดสินข้อ Q7 (§6) ก่อนเริ่มขั้น 6 — ถ้าทำตอนท้ายเฟสแล้วไม่ผ่าน จะทำให้ทั้งเฟสค้าง
**ไม่ commit โค้ด spike** · บันทึกผลเป็นภาพตัวอย่างใน PR/ข้อความรายงาน

**ผล spike (2026-09-23) — ✅ ผ่าน มีเงื่อนไข 1 ข้อ** · ทดสอบ `@react-pdf/renderer` 4.9.0 + `qrcode` 1.5.4 กับ Anuphan และ Sarabun ได้ผลเหมือนกัน
- วรรณยุกต์และสระบน/ล่างซ้อนถูกตำแหน่ง (ผู้ ปู่ ที่ นี้ ปั้น ญี่ปุ่น ศักดิ์สิทธิ์ ปั๊ม) · ฎ ฐ ญ หางไม่ชนบรรทัด · QR สแกนได้
- **บั๊ก: ข้อความที่มี `ำ` (U+0E33) ทำให้ตัวอักษรตัวสุดท้ายของข้อความนั้นหายทั้งบนภาพและในชั้นข้อความ**
  เช่น "ปิ่นทองคำ" → "ปิ่นทองคํ", "…เกี๊ยว" → "…เกี๊ย" — fontkit แตก `ำ` เป็นสอง glyph (ํ + า) แต่ layout ตัดตามจำนวนตัวอักษรเดิม
- **แก้ได้ด้วยการแตก `ำ` เป็น `ํา` ก่อนส่งเข้า PDF** — ทดสอบแล้วแสดงครบทุกตัวและหน้าตาเหมือนเดิม
  ข้อแลก: ข้อความที่คัดลอก/ค้นหาจากไฟล์ PDF จะเป็น "ํา" แทน "ำ" (ไม่กระทบหน้า `/verify/[code]` ที่เป็นแหล่งยืนยันจริง)
  → ขั้น 6 ต้องให้**ทุกข้อความ**ที่เข้า PDF ผ่านตัวแปลงจุดเดียว และมี unit test กันคนเผลอส่งข้อความดิบ
- Anuphan ใน Google Fonts เป็น variable font — react-pdf ใช้ได้แค่น้ำหนัก Regular
  ถ้าต้องการหัวข้อตัวหนา ต้องสร้างไฟล์ static (เช่น Bold) จาก variable font ด้วย fonttools ในขั้น 6
- **ข้อสรุป Q7:** ใช้ `@react-pdf/renderer` + `qrcode` ตาม design เดิม

### ขั้น 1 — M07a คลังข้อสอบ — ✅ เสร็จ 2026-09-23
- FR-07.1 คลังข้อสอบรายคอร์ส + tag · ค้นหา/กรองตาม tag และชนิด
- FR-07.2 สร้าง/แก้ข้อสอบ 6 ชนิด — โจทย์เป็น Tiptap (ใส่รูปได้), ตัวเลือก, เฉลย, คำอธิบายเฉลย, คะแนน

  · ให้ดาวน์โหลดไฟล์แม่แบบทั้งสองรูปแบบ · แปลงทั้งสองรูปแบบเป็นแถวชุดเดียวกันก่อนเข้าตัวตรวจตัวเดียว

- **Test:** unit ของ schema 6 ชนิด + ตัวอ่าน CSV/XLSX · e2e สร้างข้อสอบครบ 6 ชนิดและนำเข้าทั้ง CSV และ XLSX

**สิ่งที่ทำจริง**

| ไฟล์ | หน้าที่ |
|---|---|
| `prisma/migrations/…_question_archived_at` | S1 — `Question.archivedAt` (คอลัมน์เดียว nullable) |
| `src/features/questions/` | schema 6 ชนิด · ตัวนำเข้า (pure) · queries (กรอง/ค้น/แบ่งหน้า) · actions (สร้าง/แก้/เก็บเข้าคลัง/นำเข้า/แม่แบบ) · UI |

- นำเข้าแบบ "ทั้งหมดหรือไม่มีเลย" และ server อ่านไฟล์ใหม่ตอนยืนยัน (ไม่เชื่อผลตรวจที่ client ถือไว้) · ไฟล์ ≤ 900 KB / 500 ข้อ
- ค้นในโจทย์ด้วย `prompt::text ILIKE` แบบส่งพารามิเตอร์ — Prisma กรองข้อความที่ซ้อนใน Tiptap JSON ไม่ได้
- **พบและแก้บั๊กเดิมของ `RichTextField`:** ระหว่างที่ Tiptap ยังโหลดไม่เสร็จ ฟอร์มไม่มีช่องซ่อนของเนื้อหา
  กดบันทึกเร็วจะส่งเนื้อหาว่าง — กับฟอร์มคอร์ส/บทเรียนเดิมแปลว่าคำอธิบายหรือบทความถูกล้างทิ้ง
  ตอนนี้ตัว placeholder ส่งค่าเดิมไปแทน

  ฟอนต์ก็ไม่มี glyph ของ zero-width space — จึงวางคำละกล่องใน flex-wrap (ตัดคำด้วย `Intl.Segmenter`) · ชื่อคนและรหัสเป็นกล่องเดียว ห้ามตัดกลาง
- ตรวจด้วยตาจากไฟล์จริง (แปลงเป็นภาพด้วย PyMuPDF): วรรณยุกต์/สระบนล่างถูกที่ · `ำ` ครบ · ไม่มี "-" แทรก · ตัวหนาใช้ได้
- **ใบที่ออกแล้วไม่ถูกเพิกถอนอัตโนมัติ** แม้ภายหลังผู้เรียนหลุดเงื่อนไขจบ (เจ้าของระบบยืนยัน 2026-09-23) — เพิกถอนได้โดยผู้ดูแลเท่านั้น
- ใบที่ออกแล้วไม่เปลี่ยนตามแม่แบบใหม่ (PDF สร้างครั้งเดียว) · ชื่อผู้ได้รับในหน้า verify เป็นชื่อปัจจุบันของบัญชี
- คอร์สที่ผู้เรียนจบก่อนมี M10 → ออกใบให้ตอนเปิด `/certificates` (ไม่มี cron)
- รูปบนใบประกาศรับเฉพาะ PNG/JPEG (react-pdf อ่าน WebP ไม่ได้)
- **พบและแก้บั๊กจาก Phase 1:** จบคอร์สด้วยการดูวิดีโอถึง 90% ของบทสุดท้ายไม่เรียก `notifyCourseCompleted` —
  ไม่มีแจ้งเตือน "เรียนจบ" และจะไม่ได้ใบประกาศ · แก้แล้ว

## 4. การเปลี่ยน Prisma schema — อนุมัติแล้ว (CHANGELOG #20)

| # | เปลี่ยนอะไร | ทำไม |

## 7. ความเสี่ยงที่มองเห็นตอนนี้

| ความเสี่ยง | ผลกระทบ | แนวทาง |
|---|---|---|
| เฉลยรั่วไปที่ client | ข้อสอบเสียทั้งชุด | query ของหน้าทำข้อสอบ `select` เฉพาะฟิลด์ที่แสดง (ไม่ดึง `isCorrect`/`matchKey`) + e2e ค้นเฉลยใน HTML/RSC |
| ผู้เรียนแก้เวลาเครื่องหรือเปิดหลายแท็บ | สอบเกินเวลา / ได้ชุดข้อใหม่ | ตัดสินด้วย `expiresAt` ฝั่ง server เท่านั้น · `startAttempt` คืน attempt เดิมที่ยังเปิดอยู่แทนการสร้างใหม่ |
| สองคนส่ง/แก้คะแนนพร้อมกัน | คะแนนในสมุดไม่ตรงกับผลสอบ | sync `Grade` ใน transaction เดียวกับการส่ง/ตรวจ · unique `[gradeItemId, userId]` มีอยู่แล้ว |
| ปัดเศษคะแนน | เกรดคลาดที่ขอบ (79.995 → A หรือ B+) | คำนวณด้วย Decimal ทั้งเส้น ปัดครั้งเดียวที่ 2 ตำแหน่งตอนแสดง · unit test กรณีขอบ |
| วรรณยุกต์ไทยใน PDF | ใบประกาศใช้จริงไม่ได้ | spike ขั้น 0 ก่อนลงมือทั้งเฟส |
| เปิดให้ STUDENT อัปโหลด | ช่องทางใหม่ให้ยัดไฟล์ขยะ/มัลแวร์เข้าระบบ | ผูกกับ `assignmentId` + enrollment, จำกัดนามสกุล/ขนาดตามงาน, magic bytes เดิม, rate limit |
| ตารางสมุดคะแนนบนมือถือ | Chrome ย่อทั้งหน้า (CLAUDE.md §6) | มุมมองการ์ดบนจอเล็กแทนตารางกว้าง |
